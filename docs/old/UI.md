# UI設計

> **標準文書との関係:** フロントエンド構造と実装境界は [FRONTEND.md](FRONTEND.md) を正本とする。この文書は画面表示、操作、状態、視覚仕様を詳細化する。

## 1. 目的

この文書は、amazon-explorer のStreamlit画面で利用者が見る要素、操作手順、表示規則、エラー表現、アクセシビリティ上の現状を定義する。実装構造と状態管理は [FRONTEND.md](FRONTEND.md)、承認済みの次期画面フローは [SEARCH-FLOW.md](SEARCH-FLOW.md)を参照する。

## 2. 想定利用者と利用目的

利用者は、商品名だけでなく「静か」「白い」「1万円以内」「避けたい条件」のような要望を日本語の自然文で入力し、条件への近さを比較する。表示順位は推薦や購入保証ではなく、取得できた候補を現行スコア式で並べた参考情報である。

現行UIはローカル利用を主対象とする。ログイン、複数利用者向けの履歴管理、購入処理は提供しない。

## 3. 画面仕様

### 3.1 ページ設定

| 項目 | 現行値 |
|---|---|
| ブラウザページタイトル | `Amazon Product Search` |
| レイアウト | `wide` |
| 画面タイトル | `Amazon類似度検索` |

### 3.2 サイドバー

「設定」見出しの下に次を表示する。

| 表示 | 内容 |
|---|---|
| `Bonsai: ...` | `BONSAI_BASE_URL` の値 |
| `Amazon: ... / ...` | Outscraperのドメインと言語 |
| `取得件数: ...` | Outscraperへ要求する最大件数 |
| `Outscraper API key: existing/missing` | APIキーが空でないかだけを成功・警告表示 |
| `Bonsai Server: running/not running` | `/models` の疎通結果を成功・警告表示 |
| `表示件数` | 1から30のスライダー |

`SHOW_DEBUG_INFO=true` の場合だけ、商品名・属性・価格の総合係数と、必須語・色語・特徴語・優先語・関連語の重みをJSON表示する。採点に使う8つの重みは確認できるが、全設定の診断画面ではない。

ここで挙げた接続先、APIキー設定状態、サーバー稼働状態、debug JSONは現行Streamlitの診断表示であり、次期の通常UIへ継承しない。次期UIでは、利用者が対処できる問題が起きた場合だけ平易な案内を表示し、診断情報は運用者向けログへ分離する。

### 3.3 検索フォーム

- ラベル: `商品を検索`
- 入力形式: 高さ120pxの複数行テキスト
- 実行ボタン: `検索`
- 空白だけの入力: `検索条件を入力してください。` と警告し、検索しない

入力例:

```text
1万円以内で、白くて静かな日本語配列のワイヤレスキーボード。
テンキー付きは避けたい。
```

条件を具体化するときは、商品種別、価格帯、色、必要な特徴、避けたい特徴を一つの文章に含める。

## 4. 検索中と検索後の状態

### 4.1 検索中

検索開始後は次のスピナーを表示する。

```text
商品候補を取得してスコアリングしています。
```

検索は同期処理である。スピナーは段階別進捗、Outscraperのポーリング回数、完了予定時刻を表示しない。処理中にブラウザを閉じた場合の継続やキャンセルも保証しない。

### 4.2 0件

検索が正常終了しても表示対象がなければ、次を情報表示する。

```text
表示できる検索結果がありません。
```

0件はエラーとは限らない。Outscraperが正常に0件を返した場合や、正規化でタイトルなし・未対応通貨の商品が除外された場合にも発生する。

### 4.3 結果あり

区切り線の後に次の件数表示を行う。

```text
{取得結果数}件中 {実際の表示数}件を表示
```

`表示件数` は画面に描画する上限であり、検索済みの結果リストやOutscraperの取得件数を変更しない。スライダーを変更しただけでは再検索しない。

## 5. 商品カード

商品1件を枠付きコンテナに表示し、画像列と詳細列を1対3の比率で並べる。

| 要素 | 表示規則 |
|---|---|
| 順位・商品名 | `{順位}. {title}` を小見出しとして表示 |
| 商品画像 | `image_url` があれば列幅に合わせて表示。なければ「画像なし」 |
| 総合 | `total_score` を小数3桁で表示 |
| 商品名 | `title_similarity` を小数3桁で表示 |
| 属性 | `attribute_similarity` を小数3桁で表示 |
| 価格 | `price_score` を小数3桁で表示 |
| 進捗バー | `total_score` を0から1のバーで補助表示 |
| 実価格 | 整数を桁区切りした `{価格}円`。値がなければ「価格不明」 |
| 評価 | 小数1桁。件数があれば `{評価} / {件数}件`、なければ評価だけ。評価がなければ「評価なし」 |
| 商品リンク | `product_url` がある場合だけ「Amazonで開く」ボタン |
| 条件語 | 一致、不足、避けたい条件への一致を、それぞれ値がある場合だけ表示 |

条件語は ` / ` で連結する。「避けたい条件に一致」が表示された商品は、否定条件ペナルティを受けていても候補から自動除外されたとは限らない。

## 6. スコアの読み方

総合スコアは次の要素を組み合わせ、0から1へ制限した値である。

```text
0.45 × 商品名類似度
+ 0.35 × 属性類似度
+ 0.20 × 価格スコア
- 否定条件ペナルティ
```

- `商品名`: 入力条件と商品名のテキスト類似度
- `属性`: 商品説明等との類似度または重み付き条件一致率
- `価格`: 指定または推定価格帯への近さ
- `一致した条件`: 採点に使われた条件のうち見つかったもの
- `不足している条件`: 採点対象だが見つからなかったもの
- `避けたい条件に一致`: 商品テキスト中で見つかり、減点対象になったもの

スコアは取得データと設定に依存する。商品の品質、安全性、在庫、価格の最新性を保証しない。詳細な計算規則は [DESIGN.md](DESIGN.md) と [BACKEND.md](BACKEND.md)を参照する。

## 7. メッセージとエラー表示

| 状況 | 種別 | 利用者向け表示 | 次の行動 |
|---|---|---|---|
| 入力が空 | warning | `検索条件を入力してください。` | 商品条件を入力して再送信 |
| APIキーなし | sidebar warning | `Outscraper API key: missing` | `.env` を設定してアプリを再起動 |
| Bonsai疎通不可 | sidebar warning | `Bonsai Server: not running` | Bonsaiサーバーと接続先を確認 |
| 検索処理の例外 | error | `検索に失敗しました。設定と外部サービスの状態を確認してください。` | 起動ターミナルのログを確認 |
| 正常な0件 | info | `表示できる検索結果がありません。` | 条件を広げて再検索 |
| 商品画像なし | info | `画像なし` | 商品名やリンクで判断 |

検索例外の詳細は画面に表示しない。APIキー、外部レスポンス、スタックトレースの漏えいを避けるためである。診断方法は [TROUBLESHOOTING.md](TROUBLESHOOTING.md)を参照する。

## 8. 操作フロー

1. サイドバーで Bonsai が `running`、Outscraper API key が `existing` であることを確認する
2. 商品条件を自然文で入力する
3. 「検索」を押す
4. スピナーが消えるまで待つ
5. 総合スコアだけでなく、一致・不足・否定条件と価格を比較する
6. 必要なら表示件数を変える
7. 商品ページを確認するときだけ「Amazonで開く」を押す

商品ページの価格や在庫を最終判断の正とする。外部リンク先の内容と安全性は本アプリが保証しない。

## 9. アクセシビリティ

### 9.1 現在利用できる手掛かり

- スコアはバーだけでなく数値とラベルでも表示する
- 状態は色だけでなく `existing/missing`、`running/not running` の文字でも示す
- 価格不明、評価なし、画像なしを文字で明示する
- 検索入力にラベル、実行操作にテキスト付きボタンを使う
- 商品リンクは用途が分かる「Amazonで開く」という文言を使う

### 9.2 未確認・未実装

- 商品画像へ商品名に基づく明示的な代替テキストを設定していない
- フォーカス順、キーボードだけでの操作、スクリーンリーダー読み上げを試験していない
- エラー発生時のフォーカス移動やライブリージョンを独自実装していない
- 小画面、拡大表示、高コントラスト、色覚多様性の受入試験がない
- 日本語と英語が混在するステータス文言がある

公開範囲を広げる前に、Streamlitの生成HTMLを実際のブラウザと支援技術で確認する。未確認事項は [TECH-DEBT-TRACKER.md](TECH-DEBT-TRACKER.md) で追跡する。

## 10. UI受入確認

外部APIを呼ばない起動確認:

```sh
uv run --frozen --offline --no-sync streamlit run app.py --server.headless true
```

手動確認項目:

- ページタイトル、画面タイトル、サイドバーが表示される
- 空入力で警告が出て検索が始まらない
- 表示件数を1から30で変更できる
- APIキーの実値が画面に出ない
- Bonsai停止時も画面自体は起動し、警告表示になる
- 検索例外の詳細が画面に出ず、サーバーログには診断情報が残る
- 成功時に件数、各スコア、価格、評価、条件語、存在するリンクが表示される
- 表示件数変更だけでは検索が再実行されない

実検索を伴う確認ではOutscraperの利用料金と取得件数を事前に確認する。

## 11. 次期検索画面（承認済み・未実装）

現行の「検索」1操作で同期処理を始める画面は、次期検索フロー v2では次へ置き換える。

| 段階 | 必須表示 | 利用者操作 |
|---|---|---|
| 入力 | 自然文、2,000文字上限 | 条件を整理する |
| 条件確認 | `必ずほしい`、`できればほしい`、`避けたい`、入力価格またはAIが提案した価格の目安、参考画像トグル | 修正、参考画像を作る、画像なしで最終確認へ進む |
| 参考画像 | 正面、左側面、右側面、背面、`AI生成イメージ`、作り直せる残り回数 | 4枚をまとめて作り直す、参考画像を使わない、次へ進む |
| 最終確認 | 条件、価格、検索先、比較候補の上限（最大48件）、比較項目、画像、この承認で商品検索を1回実行すること | 修正、取消、この条件で商品を探す |
| 待機 | `商品を探す`、`商品情報を整理`、`商品の特徴を確認`、`希望条件と比較`、`結果を準備` の5段階と、右側へ常時表示する読み取り専用の検索条件要約 | 完了を待つ、許可された場合だけ中止する |
| 取得・評価完了 | 完了した5段階、確定した商品件数、平易な注意事項 | 結果を見る、条件を見直す |
| 結果 | 条件に近い順、比較済み件数と表示件数、条件との近さ、希望に合う点、商品説明では確認できない点、避けたい条件への該当 | 1〜30件で表示件数を変更、外部商品ページを開く、新しい検索 |
| 検索履歴 | 検索日時、条件要約、価格条件、参考画像利用の有無、比較件数 | 保存済み結果を開く、1件ずつ削除、商品を探す |

共通ヘッダー右側へ追加するグローバル操作は `検索履歴` だけとし、検索中の画面から履歴一覧へ移動できるようにする。設定ボタンと設定画面は初回実装を保留し、無効な設定ボタンや空の設定画面を先行配置しない。

参考画像トグルは既定OFFとする。作り直しは4枚一括で、変更後は旧画像と最終確認を無効にする。単に最終確認画面を開いただけでは検索を始めず、`この条件で商品を探す` の明示操作だけを承認とする。

参考画像は4枚1組を1回と数え、1計画で初回生成と一括作り直しを合わせて2回までとする。初回生成前は `参考画像を使う（残り2回）`、初回生成後は `作り直せる回数：残り1回`、作り直し実行後は `残り0回` と表示する。この回数は画像setの作成回数であり、画像枚数やAPI call数ではない。最終確認には `この承認で商品検索を1回実行します` と表示し、検索クォータの残数とは表現しない。再試行は固定値を仮定せず、サーバーが残数を返せる場合だけ `もう一度試せる回数：残りN回`、返せない場合は `再試行できます` または `再試行できません` と表示する。通常画面には外部APIの単価、見積額、合計額、金額上限を表示または入力させず、内部の費用上限はサーバーがfail closedで強制する。

正常に比較が完了した検索は、0件だった場合を含めて検索履歴へ1件として完了日時から30日間自動保存する。履歴カードには分単位の保存期限を表示する。履歴を開いたときは保存済みの条件と順位付け結果を描画するだけとし、画像生成、商品取得、商品属性整理、採点を再実行しない。履歴一覧の空、読込中、読込失敗、1件削除中、削除失敗を別の状態として表示する。履歴項目の個別削除は復元不能であることを確認ダイアログに示し、成功するまでカードを一覧から外さない。30日の期限へ到達した履歴と専有生成画像はサーバー側で物理削除し、外部処理から再構築しない。

履歴は表示用スナップショットだけを通常画面へ返す。郵便番号、お届け先、検索要求parameter、内部ID、外部サービス名、model名、token数、digest、raw score、内部評価方式は、現在結果と履歴のどちらにも表示しない。

待機画面の検索条件要約には、承認済みの条件、価格、検索先、比較候補の上限、参考画像利用の有無を表示する。右側へ常時表示するページ内サイドビューとし、開閉ボタン、overlay、Sheetは設けない。郵便番号、お届け先、検索語、内部情報は表示しない。

### 11.1 モーダル化する範囲

次期UIでページから切り離すのは、短い確認または補助参照だけである。

| 形式 | 対象 |
|---|---|
| 画像ライトボックス | 4方向参考画像の1枚拡大、前後移動、閉じる |
| 確認ダイアログ | 4画像の一括作り直し、安全に取消可能な検索の中止、復元不能時だけの新しい検索、外部処理を行う再試行、履歴1件の削除 |

検索語編集、待機中の読み取り専用条件要約、商品詳細は現行のページ内要素を維持する。条件入力、最終確認、待機、結果、履歴一覧をモーダルへ入れない。保存済み結果から `新しい検索` を始める場合は復元可能なので確認ダイアログを表示せず、履歴保存に失敗した場合だけ表示する。

モーダル系部品は同時に1つだけ開く。背景を操作不能にし、開いたときに安全な要素へフォーカスを移し、閉じた後は起動元へ戻す。`Esc` とキャンセルは実行操作を起こさない。ダイアログ内に別のダイアログを重ねない。

通常画面にはsession／run／request等の内部ID、外部サービス名、model名、attempt、digest、hash、証拠値、API call数、token数、JSON、TF-IDF、CLIP、pHash、Hamming距離、ranking profile、raw score、内部component、実weight、採用言語、外部APIの料金情報を表示しない。必要な技術情報はサーバー側へ保持し、運用者向けログまたは権限を分離した診断画面だけで確認する。

## 12. 次期フロント実装のデザインシート

次期フロントはデスクトップ版だけを対象とし、タブレット／モバイル用frame、breakpoint、responsive variantは作らない。実装時は次のFigmaデザインシートを利用する。

- [amazon-explorer｜検索フロー UI Design Sheet v2](https://www.figma.com/design/PEVM5G4854vaDqdWgSA3ui): Foundations、編集可能なcomponent／variant、Intent Review、Reference Images、Image & Approval、Waiting、Acquisition & Evaluation、Results、Historyとモーダル系状態のデスクトップ画面
- [次期UIの人間向け操作フロー](../UI-FLOW.md): 画面で確認する内容、押すボタン、次に起きること、API利用前の確認
- [主要検索フロー（デスクトップPNG）](assets/ui-reference/search-flow-desktop-v1.png): Figmaと文章仕様を比較するためのラスタ参照

`Screens / Reference Images` は4方向画像の確認・一括作り直し・採用判断を、`Screens / Waiting` は商品検索中の5段階を、`Screens / Acquisition & Evaluation` は5段階が完了した状態を示す完成サンプルである。通常画面の視覚正本はFigmaとし、技術バックエンド契約は [SEARCH-FLOW.md](SEARCH-FLOW.md) を正とする。PNGは旧構図との比較用であり、内部情報を含む古い表示文言を新画面へ継承しない。過去に作成した `components-responsive-v1.png` のタブレット／モバイル案は現行スコープに含めない。

## 13. 次期UIの視覚統一契約

次期デスクトップUIは、FigmaのSemantic Color、Spacing、Radius、Typographyを視覚上の正本とする。React／Tailwind実装でも同じ役割名と値へ対応させ、画面ごとの任意色、任意の文字サイズ、任意の余白を追加しない。商品画像とAI生成画像の画素色は、この制約の対象外である。

### 13.1 配色

背景、文字、境界線には次のSemantic Colorだけを使う。16進数は実装照合用であり、コンポーネントからはPrimitive ColorではなくSemantic Colorを参照する。

| 用途 | Semantic Color | 値 | 使用範囲 |
|---|---|---|---|
| 画面背景 | `color/bg/canvas` | `#F9FAFB` | アプリ全体の背景 |
| 基本面 | `color/bg/surface` | `#FFFFFF` | ヘッダー、カード、入力欄 |
| 補助面 | `color/bg/subtle` | `#F3F4F6` | 二次領域、待機中の仮表示 |
| ブランド | `color/bg/brand` | `#4F46E5` | 主要操作、現在Step |
| ブランド補助面 | `color/bg/brand-subtle` | `#EEF2FF` | 選択中、注目させる補助領域 |
| 成功 | `color/bg/success` / `color/bg/success-strong` / `color/text/success` / `color/border/success` | `#ECFDF5` / `#059669` / `#047857` / `#059669` | 完了状態だけ |
| 注意 | `color/bg/warning` / `color/bg/warning-strong` / `color/text/warning` / `color/border/warning` | `#FFFBEB` / `#D97706` / `#B45309` / `#D97706` | 利用者の確認が必要な状態だけ |
| エラー | `color/bg/error` / `color/text/error` / `color/border/error` | `#FEF2F2` / `#B91C1C` / `#DC2626` | 入力エラー、処理失敗だけ |
| 主文字 | `color/text/primary` | `#0F172A` | 見出し、主要な値 |
| 副文字 | `color/text/secondary` | `#4B5563` | 本文、補足説明 |
| 弱い文字 | `color/text/muted` | `#6B7280` | 注釈、未到達状態 |
| 反転文字 | `color/text/inverse` | `#FFFFFF` | ブランド背景上の文字 |
| ブランド文字 | `color/text/brand` | `#4338CA` | リンク、選択状態の文字 |
| 基本境界 | `color/border/default` | `#D1D5DB` | 入力欄、カード |
| 弱い境界 | `color/border/subtle` | `#E5E7EB` | 区切り、低強調の枠 |
| フォーカス | `color/border/focus` | `#6366F1` | キーボードフォーカス |

成功、注意、エラーは装飾目的で使わず、必ずアイコンまたは状態文言を併記する。主要操作はブランド色、補助操作は白い面と基本境界、無効状態は補助面と弱い文字へ統一する。

### 13.3 幅、高さ、余白、角丸

- デスクトップframeは幅1,440px、主要コンテンツは幅1,120pxで中央配置し、左右を各160pxとする。
- 7つの利用者向け画面は、外周を上32px・左右48px・下48px、直下の主要ブロック間を24pxに統一する。主要コンテンツはこの外周内で中央配置する。
- 参考画像は幅256pxを4列、結果カード、待機中カード、履歴カードは幅352pxを3列とし、いずれも列間を32pxにする。カードを縮尺指定で押し込まず、インスタンスは常に1倍で配置する。
- 単行入力、主要／補助ボタン、選択トリガーは高さ44pxに統一する。複数行入力、画像カード、進捗行は内容に応じた既定コンポーネントの高さを使う。
- 余白は4 / 8 / 12 / 16 / 24 / 32 / 48pxだけを使う。アイコンと文字は4または8px、同一グループ内は8または12px、フォーム項目間は16px、カード内余白と主要ブロック間は24px、セクション間は32または48pxを基準とする。
- 角丸は6 / 10 / 14pxと完全な円形だけを使う。小さな状態部品は6px、入力と小型パネルは10px、カードと主要パネルは14px、Badge、Chip、Toggleつまみ、円形アイコンは`radius/full`とする。
- カードは基本面、1pxの基本境界、24pxの内側余白、14pxの角丸を標準とする。浮上を伝える必要がない通常カードへ強い影を追加しない。

### 13.4 実装と確認

Button、Field、Toggle、Chip、Stepper、App Header、画像カード、進捗行、待機中の条件要約、結果カード、履歴カード、Overlay、Dialog、AlertDialog、Image LightboxはFigmaの共通コンポーネントへ揃え、画面内で類似部品を複製して別仕様にしない。例外が必要な場合は、先にFigmaの変数またはコンポーネントを更新し、この節とReact／Tailwind側のthemeを同じ変更で更新する。

受入確認では、7つの利用者向け画面について、主要コンテンツ幅、44pxコントロール、文字スタイル、余白、角丸、Semantic Color参照を比較する。状態差は色だけでなく文字でも判別できることを確認する。
